# Fidelity — compiler artifacts, idiom restoration, equivalence

Companion to `SKILL.md`. Bytecode is a compiled lowering of source, not the source
itself. Recover the author-level construct the evidence supports; never
transliterate desugared bytecode into the project.

## 1. Desugaring catalog (pattern → restoration)

| Bytecode pattern | Author-level construct | Notes |
|---|---|---|
| `invokedynamic` + lambda-factory bootstrap; body in a private synthetic `lambda$…` method | Lambda expression | A direct method-handle target means a method reference, not a lambda body |
| `invokedynamic` concatenation bootstrap (newer targets) or builder chains (older targets) | String concatenation `+` | The bootstrap recipe carries the exact constant layout |
| `$VALUES`, generated `values`/`valueOf`, `$SwitchMap` holder class | Enum declaration; switch over enum | Generated members are not author code |
| hashCode switch + equals ladder + index switch | Switch over strings | |
| Switch bootstraps on newer targets | Pattern-matching switch | Verify target support before restoring |
| `this$0`, `val$…` captures, inner-class records | Inner / anonymous / local classes | Nestmates (11+) vs access bridges (older) reflect the target, not author choice |
| Bridge methods + `Signature` attributes | Generics | Never emit bridges; restore type arguments from signatures |
| close/addSuppressed scaffolding (shape varies by compiler family and version) | try-with-resources | Recognize the pattern, not one exact shape |
| Assertion-disable flag + branch | `assert` | |
| `Record` attribute + generated members | `record` | Components are authoritative |
| `PermittedSubclasses` | `sealed` / `permits` | |
| Boxing/unboxing calls, varargs flag, iterator or index loops | Autoboxing, varargs, enhanced for | Several source spellings lower identically — pick the idiomatic one |
| Class/instance initializer code | Field initializers vs initializer blocks | Line numbers help distinguish |

Rules:

- Never emit synthetic or bridge members as source.
- Where two source forms compile to identical semantics, either is faithful;
  prefer the idiomatic form. Do not inflate INFERRED labels over surface syntax.
- Restore at the language level the class-file version supports; preview flags
  require a matching toolchain in preview mode.

## 2. Non-Java JVM languages

- **Kotlin:** the `kotlin.Metadata` annotation carries original declarations —
  names, nullability, properties, default parameters, suspend. `$default`
  synthetics with bitmasks, inserted intrinsic null checks, companion/object
  machinery, and suspend state machines (continuation + label switch) are
  compiler artifacts. A Java-only rendering loses nullability and defaults:
  declare the loss or recover language-aware.
- **Scala:** signature annotations/attributes carry the real declarations.
  Traits lower to interfaces plus implementation classes; objects to `MODULE$`
  holders; case classes to generated product machinery. Java output is a lossy
  projection — label it as such.
- **Groovy:** dynamic call-site machinery dominates the bytecode; a static Java
  reconstruction misrepresents semantics. Declare the language and the limits.
- **Runtime-generated code:** proxies and generated bytecode have no source.
  Document the generator and its inputs instead of fabricating classes.

## 3. Verification protocol

1. **Target selection.** Derive the compilation target from the class-file major
   version; verify the mapping against a current reference. Offline: state the
   assumed mapping and confirm it empirically at compile time. Preview minor
   version → matching JDK with preview enabled.
2. **Compile.** Classify every error before fixing: recovery defect, missing or
   wrong dependency, language-level mismatch. Fix only from evidence; never
   change behavior to silence a compiler.
3. **Normalize before comparing.** Strip debug attributes; resolve constant-pool
   indices to content; canonicalize member order; ignore stack-map frames.
   Compare disassembly, not raw bytes.
4. **Expect legitimate variance.** Compiler families and JDK versions differ in
   concatenation bootstrap shape, try-with-resources lowering, branch layout,
   synthetic naming, and debug emission. Byte identity is strong evidence when
   it happens — never a requirement, never a goal to force.
5. **Compare semantics.** Signatures, flags, annotations, constants; per-method
   instruction semantics modulo documented variance; exception tables;
   bootstrap arguments. Every remaining difference is either justified in
   writing or it blocks verification.
6. **Verdicts.**
   - Identical after normalization → verified.
   - Equivalent with a written justification for each difference → verified.
   - Any unexplained difference → not verified; status stays RECONSTRUCTED or lower.
   - Behavioral comparison → only with justified, isolated execution.
7. **Coverage ledger.** Member → verification method (manual semantic check /
   normalized bytecode comparison / structural check) → result. Logic-bearing
   members need semantic verification. Mechanical members (trivial accessors,
   constant holders, generated record members) may be verified structurally in
   batches: descriptors, flags, annotations, constants, trivial body shape.
   Report counts per status. Never sample silently; never blanket-promote.

Compilation success alone never promotes a status. A tool's confidence score
never promotes a status. Only evidence does.
